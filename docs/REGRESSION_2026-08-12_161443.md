# v0.5.8 實機回歸：輸入、HUD 位置與技能歸屬

狀態：**confirmed / release blocker**
證據來源：`錄製內容 2026-08-12 161443.mp4`、同次 `UE4SS.log`、`skill_dps_hud_overlay.log`。
實機環境：Palworld 1.0、UE4SS v3.0.1 Beta #0 (`c838a8ac`)、`PalSkillDPSAnalyzerSP v0.5.8`。

本文件只記錄已由影片或日誌確認的行為；推測與後續設計另列於「根因與修正方向」。

## 已確認問題

### UI-INPUT-001：F1 面板顯示，但控制項未收到滑鼠命令

- 約 69.7 秒開啟面板，游標可見。
- 約 70.5–73.5 秒游標停在頁籤、箭頭與內容區，沒有任何選取或設定變化。
- 同次 overlay log 從啟動到關閉只有 `starting`／`closed`，成功按鈕命令回執為 **0**。
- 約 75.5 秒 Palworld 原生 `OPTIONS` 反而在面板後方開啟，證明輸入仍漏到遊戲。
- 面板開啟時遊戲鏡頭／角色已被 Lua 鎖住，形成「遊戲不能操作、面板也不能操作」。

### UI-FOCUS-002：外部 WPF 與 Palworld 爭奪焦點及游標

- Lua 同時呼叫 `SetIgnoreLookInput`、`SetIgnoreMoveInput`、Controller/Pawn `DisableInput` 與 `bShowMouseCursor=true`。
- WPF 另行呼叫 `SetForegroundWindow`、`Activate`、`Focus`、`ShowCursor`，並每 200 ms 解除 `ClipCursor`。
- Unreal 沒有切換至 `UIOnly`／`GameAndUI` InputMode；Windows 也可能拒絕跨行程搶前景，而程式未驗證結果。
- UE4SS 與 WPF 都處理 F1；同一次按鍵在焦點轉移時可能同時觸發開啟與關閉。

### HUD-POS-003：戰鬥 HUD 在左右錨點間交替跳動

- 約 127–138 秒，戰鬥 HUD 在左上與右上幾乎每次刷新交替出現。
- 使用者設定為左側安全區，右上位置不應被採用。
- 外部視窗使用 `SizeToContent`，又按 `ActualWidth` 週期定位；設定／結果刷新會清空重建內容樹並再次定位，造成抖動與焦點遺失。

### ATTR-DIAMOND-004：晶鑽之雨／冰晶落地傷害沒有形成技能列

- 約 97–141 秒可見多次白色冰晶落下、冰爆與延遲命中。
- 畫面也出現紫色光束、綠色旋風及其他不同攻擊效果。
- HUD 從約 103 秒到 141 秒始終只顯示 `普攻｜暗能彈`，沒有晶鑽之雨或任何冰技能列。

### ATTR-MERGE-005：不同技能傷害全部錯併到普攻

- HUD 從 `DMG 171 ×1` 累計到 `DMG 1,886 ×10`，全數歸到 `普攻｜暗能彈`。
- UE4SS log 只記錄最初三筆 `GravityShot` 樣本（45、45、41）；這是每候選最多三筆的診斷樣本上限，不代表後續傷害回呼停止。HUD 總傷持續增加，證明收集器仍有收到後續命中。
- 三筆樣本的 `DamageCauser=none`、`attribution.Source=current_action`；當下 `GetCurrentAction()` 是 `GravityShot`，因此它在延遲冰雨落地時搶先覆蓋剛完成的 `DiamondFall`。
- 這不是傷害漏算，而是技能來源的優先序錯誤：有效的補招／普攻動作被當成強證據，導致延遲主技能全部被冒名。

### NATIVE-PACK-006：原生傷害收集器未進入獨立 Mod 執行路徑

- 日誌明確顯示：`using Lua damage hook fallback: native collector unavailable`。
- 工作坊 `Info.json` 只有 Lua InstallRule，建置腳本也沒有封裝 `native/build-native/main.dll`。
- 現有 C++ 原型只向舊名稱 `BossDPSBroadcast` 註冊 Lua API，函式名也仍是 `BossDPSNative*`；即使直接放入 DLL，`PalSkillDPSAnalyzerSP` 仍不會取得 API。
- 原型鎖定舊 UE4SS commit `c2ac246...`，實機是 `c838a8ac`，必須以目前執行檔重新建置與驗證。

### TEST-GAP-007：離線測試把錯誤輸入架構測成通過

- Lua 測試只檢查 stub 是否收到 `DisableInput`／游標呼叫，不驗證 Slate/InputMode 是否取得實際點擊。
- WPF `ValidationMode` 不建立真實 HWND，不會執行跨行程焦點、`ClipCursor`、真實滑鼠點擊與視窗定位競爭。
- 現有 `desired size`／`tab stable` 只驗離線 Measure，無法捕捉 `SizeToContent` 的兩段定位與週期性重建。

### ATTR-HOOK-008：Waza 後置回呼把 ReturnValue 放錯位置

- UE4SS 的原生程式明確把非 void `ReturnValue` 放在 post callback 的 Context 之後，再依序放原函式參數。
- v0.5.8 卻把 ReturnValue 當成最後一個參數，導致 `attacker` 實際收到 DamageInfo、`defender` 收到 attacker、`waza_type` 收到前一個參數。
- `capture_waza_marker` 因此在實機拿不到有效 attacker／defender／WazaID；這與同場日誌 `waza-marker=0` 完全一致。
- 舊測試也用同一個錯誤順序模擬 post callback，所以沒有抓到偏移。回歸 fixture 已改成 UE4SS 的真實順序。

## 已檢查的本機參考 Mod

- PerfProbe `2.002.9`：互動設定整合 Palworld 原生 Esc/CommonUI；使用 `UCommonActivatableWidget:ActivateWidget()` 讓遊戲接管 InputConfig 與焦點。傷害表是原生 UMG，建立一次後原位更新。
- SimpleDPS `1.1.0`：LogicMod 內含遊戲內 `WBP_DPSDisplay`，不是外部桌面視窗。
- 不要查我 DPS `1.2.0`：Lua Boss／玩家統計，沒有可解決本案 F1 互動的 UI 架構。
- Healing Partner Skill Overhaul：用途為夥伴技能／治療調整，不能作為 DPS 設定面板參考。

以上只採工程原則，不複製第三方程式，也不把任何一個 Mod 變成必要依賴。

## 根因與修正方向

1. 停止以外部 WPF 承擔互動設定。F1 設定改成遊戲內 CommonUI／UMG，由遊戲擁有游標與輸入模式。
2. 移除外部面板的 `DisableInput`、`ShowCursor`、`ClipCursor`、`SetForegroundWindow` 競爭；原生 UI 未完成時要 fail closed，不能再把玩家鎖住。
3. DPS 顯示也改成遊戲內 UMG；UI 樹只建立一次，資料刷新只更新現有文字、長條與顯示狀態。
4. 將原生傷害收集器改名並綁定 `PalSkillDPSAnalyzerSP`，針對實機 UE4SS 版本建置，且封裝進工作坊內容。
5. 在 `MakeDamageInfoByWazaType` 的後置回呼取得 `ReturnValue`／DamageInfo 身份，再與最終 `OnDamage` 事件串接；不得只讀當下動作名稱。
6. 以 attacker＋defender＋高精度時間＋sequence/cast key 的有界佇列保存並行技能；無法證明時進 `未歸屬傷害`，不得默認併入當下或最近的普攻。

## 發布前實機驗收

- F1 開啟後游標可見，所有按鈕可點；點擊不會投擲、射擊或開啟原生 Options。
- F1／Esc 每次只切換一次；關閉後移動、鏡頭、攻擊與游標完整恢復。
- 設定頁與本次測試尺寸固定；開啟 10 秒位置偏移不超過 1 px，UI 樹只建立一次。
- 戰鬥 HUD 連續 60 秒不左右換邊、不反覆顯示／隱藏。
- 單獨施放晶鑽之雨時，直擊、延遲落地與冰霧命中全數回到晶鑽之雨；不得顯示為暗能彈。
- 同場依序施放暗能彈、晶鑽之雨、紫色光束與旋風時，至少形成各自技能列；證據不足者顯示未歸屬，不得全部併到普攻。
- 覆蓋 Alt+Tab、不同 DPI／解析度、背包／Options、返回標題、世界切換。
- 測試時只啟用本 Mod 與必要前置；PerfProbe、SimpleDPS、不要查我 DPS 等其他傷害 Hook 全部暫時停用。
