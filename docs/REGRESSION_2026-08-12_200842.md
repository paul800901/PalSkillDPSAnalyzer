# v0.5.9 實機回歸：F1／F2、HUD 跳動、技能分類與歸屬

狀態：**confirmed / release blocker**
證據來源：`錄製內容 2026-08-12 200842.mp4`（192.939 秒）、同次 `UE4SS.log`、`skill_dps_hud_overlay.log`、目前工作區程式碼。
實機版本：Palworld `v1.0.3.101283`（影片左上角）、`PalSkillDPSAnalyzerSP v0.5.9-attribution-failsafe-diagnostic`（UE4SS 啟動日誌）。

本文件只記錄影片、同次日誌或目前程式碼能確認的事實。離線測試結果與實機結果分開判讀；本次沒有修改遊戲功能。

## 結論

`v0.5.9` **沒有通過實機驗收，不可當作已修復版發布**。

- F1 按鍵有收到，但程式主動拒絕開啟，玩家沒有任何畫面提示；目前實際上不存在可用設定頁。
- F2 確實有歸零，但歸零後把 HUD 隱藏，沒有成功提示，連續按鍵還會重複重設，所以玩家看不出是否生效。
- HUD 在設定為 `left-center` 時仍會左右換邊；15.5→16.0 秒及 90.0→90.5 秒都有 0.5 秒內由右側跳到左側的直接證據。
- 本 Mod 的產品定義是：帕魯當下三個裝備技能以外、由帕魯自行施放的攻擊都歸為「普攻」。這個定義成立；目前的錯誤是換技能後沒有更新 EquipWaza 快取，導致新裝備技能仍被誤標成普攻。
- 晶鑽之雨已不再全部消失，但 64 筆樣本仍全靠最近完成動作的時間推定；實機精確 DamageInfo 配對為 **0 次**，多技能重疊時仍不能保證歸屬正確。

## 已確認問題

### UI-SETTINGS-009：F1 有收到，但設定功能實際不存在

- 同次 UE4SS log 在 `20:05:06.542`、`20:05:07.889`（以及錄影前後多次）記錄：
  `F1 settings refused: native CommonUI settings page is not ready; external input path disabled`。
- `Scripts/hud.lua:1002-1015` 在 `EnableExternalHUDSettings ~= true` 時直接回傳 `false`，不會建立任何設定頁。
- 因此「F1 按了沒反應」不是按鍵 Hook 壞掉，而是 v0.5.9 刻意停用舊 WPF 互動路徑後，尚未完成 CommonUI／UMG 替代品。
- 目前拒絕動作只寫進 UE4SS log，遊戲畫面沒有「設定尚未提供」提示，使用者不可能知道發生了什麼。

**判定：** 這是功能缺失，不是可接受的最終止血。F1 原生設定頁完成前，不能宣稱此 Mod 有可調整面板。

### UI-RESET-010：F2 有歸零，但沒有玩家可見回饋

- 同次日誌在 `20:05:06.984`、`20:05:07.370`、`20:05:07.570`、`20:05:08.131` 連續記錄 `diagnostic reset` 與 `damage test reset via F2`；F2 確實有生效。
- `hud.lua:896-903` 先設定 `reset_notice`，但 `reset_skill_diagnostics()` 又呼叫 `skill_hud:clear()`；`hud.lua:1202-1206` 在沒有最新快照時直接寫入隱藏狀態。
- 結果是玩家只看到 HUD 消失，沒有「已歸零，等待第一下命中」的短暫提示。
- 0.2–0.6 秒內連按會重複建立／清除測試；目前沒有按鍵邊緣判定或防連發，單次使用意圖可能產生多筆 reset。

**判定：** 重設核心可用，但互動回饋與防連發不合格。

### HUD-POS-011：v0.5.9 戰鬥 HUD 仍在左右錨點間跳動

影片直接證據：

- 15.5 秒：HUD 位於右側，`DMG 102`；16.0 秒：同一場、同一列晶鑽之雨，HUD 移到左側，`DMG 137`。
- 90.0 秒：HUD 位於右側，`DMG 1,442`；90.5 秒：HUD 移到左側，`DMG 1,506`。
- 142.5 秒位於左側，145.0 秒位於右側；戰鬥中持續重現，不是只在第一次顯示時發生。
- 實機 `user_settings.lua` 與最後 state 都是 `anchor=left-center`，沒有合法理由切到右側。
- 本次 overlay run 只有一個 PID，日誌只有 `starting`／`closed`，沒有例外，也沒有第二個互動命令；不能用「兩個 Mod 面板互相覆蓋」解釋。

程式風險：

- `skill_dps_overlay.ps1` 每 200 ms 呼叫一次 `Set-HudPosition`。
- 每個 HUD sequence 又以 `Dispatcher.BeginInvoke` 排入另一個定位動作。
- 每次資料更新都 `contentHost.Children.Clear()` 並重建整棵 meter UI。
- 離線 desired-size 測試沒有建立／追蹤實機 HWND 的每次視窗矩形，因此先前「固定尺寸已修正」的測試不能證明位置穩定。

目前程式所有正常分支都應把 `left-center` 放到左側，所以**造成右側位置的最後一個實機來源仍未定位完成**。下一版必須先記錄每次 state sequence、anchor、Window.Left/Top、實際 HWND rect 與寫入來源；在找到第二個位置寫入者前，不可再以推測宣稱已修好。

### ATTR-CATEGORY-012：「普攻」定義成立，但換技後的舊快取造成誤標

目前 HUD 中可見：

- `普攻｜暗能彈`
- `普攻｜極寒雙星`
- `普攻｜鑽石星辰`

依本 Mod 的明確產品定義，帕魯只有當下裝備的三個技能屬於技能列；除此之外由帕魯自行施放的攻擊都列為「普攻」。因此暗能彈若不在三個裝備格內，顯示 `普攻｜暗能彈` 是正確的；極寒雙星與鑽石星辰在影片後段已被裝備，卻仍標普攻，才是本次 Bug。

程式根因：

- `main.lua:1330-1344` 的 `skill_candidate_category()` 規則是：有讀到 EquipWaza 後，只要候選 Waza ID／代碼不在該清單，就回傳 `basic`。這符合本 Mod「三個裝備技能以外皆為普攻」的定義，前提是 EquipWaza 必須是當下最新清單。
- 更嚴重的是 `refresh_equipped_waza()` 在 `main.lua:1282-1284` 只要曾成功讀到一個技能就永久提前返回。
- 本次實機只有一筆：`equipped-waza source=夜幕魔蝠 count=1 codes=DiamondFall`（20:05:21.933）。影片後段更換技能後沒有任何重新讀取；因此極寒雙星、鑽石星辰仍被舊清單判成 `basic`。

**正確語意：**

- 當下已裝備三格：顯示正式技能名稱，不加前綴。
- 不在當下三格內、但由帕魯自行施放：顯示 `普攻｜技能名稱`。
- 清單過期、未讀到或證據不足：必須先重新讀取當下三格；在完成刷新前不可沿用舊清單判定。
- 換技能、換帕魯、重新召喚或開始新測試後，都必須使 EquipWaza 快取失效並重新讀取。

### ATTR-IDENTITY-013：離線 DamageInfo 身份測試通過，但實機配對為 0

- 同次日誌共有 17 筆 `waza-marker`，後段極寒雙星／鑽石星辰都有 `damage_info=captured`。
- 但 `waza-match source=damage_info` 在整次實機 run 中為 **0 筆**。
- 極寒雙星 14 筆、鑽石星辰 7 筆最終傷害全部使用較弱的 `attribution.Source=waza_marker`，不是 `waza_damage_info`。
- 代表 `MakeDamageInfoByWazaType` ReturnValue 的 Lua 身份，沒有在最終 `OnDamage` 的 DamageResult 中原樣保留；遊戲可能複製、包裝或改成另一個結構。

離線測試使用同一個 fixture 物件餵入建立與最終傷害，所以能得到 `waza-match source=damage_info`；這項通過只證明演算法在「身份不變」的假資料成立，不能證明實機鏈路成立。

### ATTR-DIAMOND-014：晶鑽之雨有累加，但仍是時間推定，不是精確歸屬

- 影片 15.5 秒 HUD 首次顯示晶鑽之雨 `DMG 102`，16.0 秒為 `DMG 137`；總傷算術與畫面命中數值可對上。
- 日誌 20:05:17.359 捕捉 `DiamondFall` action begin，20:05:20.173 action end；第一批延遲冰雨在 20:05:21.931 後命中。
- 晶鑽之雨 64 筆、樣本傷害合計 2,115，全部標記為 `recent_completed_action_over_current_basic`。
- 沒有任何一筆使用 `waza_damage_info` 或 `damage_causer_asset`；`DamageCauser=none`。
- 同場又有暗能彈自動補招，所以目前只是「最近完成的晶鑽之雨優先蓋過當下暗能彈」的時間窗規則。單一技能測試看起來合理，但兩個延遲技能重疊時仍可能串錯施放。

**判定：** 晶鑽之雨從「整場錯併暗能彈」改善為「能被時間規則辨識」，但還不能稱為完整精準歸屬。

## 對 DeepSeek 審查結果的核對

使用者提供的 DeepSeek 審查中，以下內容可採用：

- v0.5.8 的 WPF 互動架構與 Waza post callback 參數順序確實有問題。
- v0.5.9 已停用外部互動設定、修正 ReturnValue 參數位置，並加入 DamageInfo 身份配對設計。
- `tests/run_all.ps1` 原先依賴本機沒有的 `rg`；DeepSeek 已改用 `Select-String`。本輪重新執行測試，確實以 exit code 0 完成 17 語言與離線整合測試。

但以下結論不能採用：

- 「v0.5.9 已實地驗證歸因正確」：不成立。DeepSeek 所列的 `waza-match source=damage_info` 來自離線 fixture；最新實機 run 為 0。
- 「固定尺寸已解決左右跳動」：不成立。最新 192.939 秒影片仍多次在 0.5 秒內跨邊。
- 「F1 已止血所以只剩 CommonUI」：只完成了避免再次鎖滑鼠的 fail-closed；對使用者而言設定功能仍缺失，而且沒有畫面回饋。

DeepSeek 的 `Select-String` 測試腳本修改是現有未提交變更，本報告不把它算成本輪實作，也沒有替使用者回退。

## 離線測試缺口

本輪重新執行 `tests/run_all.ps1`：**exit code 0，所有離線檢查通過**。但實機影片仍失敗，證明測試缺少至少以下條件：

1. 真實 HWND 連續 60 秒位置追蹤；每幀／每次 state update 的左右偏移不得超過 1 px。
2. 真實 Palworld 中 F1/F2 的玩家可見回饋、按鍵防連發與 menu 狀態。
3. 更換 EquipWaza 後重新讀取三格技能，分類於 1 秒內更新；三格外攻擊維持「普攻」。
4. DamageInfo ReturnValue 被複製／包裝後，身份不同但仍能以可驗證鍵串到 final damage；若串不到必須 fail closed。
5. 兩個延遲技能與普攻同時命中同一目標的回歸 fixture。
6. 背包、帕魯狀態、Options、標題畫面與 Alt+Tab 時的 HUD 可見性。

## 下一版最低驗收門檻

- F1 開啟真正的原生 CommonUI／UMG 設定頁；若尚未完成，遊戲內必須明確提示「設定功能尚未提供」，不能靜默。
- F2 每次按下只重設一次，HUD 顯示 1–2 秒「已歸零，等待命中」，之後才隱藏或進待命狀態。
- HUD 固定單一錨點，連續 60 秒與 500 次資料更新的位置偏移不超過 1 px。
- 每次開始測試、換帕魯或換技能後重新讀取 EquipWaza；當下三格不得標普攻，三格外攻擊則統一標普攻。
- 晶鑽之雨、極寒雙星、鑽石星辰分別單獨與重疊測試；精確證據缺失時顯示「待歸屬」，不能依時間窗強行認定。
- 最終報告能逐筆追溯：施放 sequence → Waza → 子效果／延遲命中 → final ActualDamage → HUD 技能列。

## 發布判定

`v0.5.9-attribution-failsafe-diagnostic`：**部分改善、實機回歸失敗、不可發布為完成版。**

可保留的成果是：最終傷害有收集、晶鑽之雨可被弱規則辨識、F2 核心歸零可用、舊 WPF 輸入鎖死路徑已停用。尚未完成的是：可用設定頁、重設回饋、HUD 位置穩定、換技後的分類刷新與可證明的延遲傷害歸屬。
