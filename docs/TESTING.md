# 測試說明

## 離線測試

在專案根目錄執行：

```powershell
powershell -ExecutionPolicy Bypass -File .\tests\run_all.ps1
```

測試不存取 Palworld 程序或遊戲檔案，涵蓋：

- Lua 語法、UTF-8、工作坊結構與相依項目。
- 外部 WPF 純顯示儀表、固定視窗尺寸、隱藏啟動器及 F1 互動 fail-closed 的執行期解析。
- 傷害回呼不直接存取 UObject。
- Boss 擊殺、捕捉、逾時與複合 Boss 生命週期。
- 手動測試從第一下開始、跨一般野生帕魯／Boss 多目標持續記錄，且可隨時歸零重新待命。
- 帕魯、騎乘技能與人物武器的來源歸屬。
- 同一測試內的不同帕魯個體及其技能不互相合併。
- 人物傷害預設關閉及可選開啟。
- 同一技能／武器候選的傷害與命中聚合。
- 每隻帕魯實際裝備三技能與冷卻補招「普攻」分類。
- 同一技能的直擊、延遲彈與地面爆炸在即時 HUD 合併，且不破壞原始診斷資料。
- 無法唯一歸因的延遲、灼燒或異常候選顯示為「未歸屬傷害」，且預設不露出內部英文代碼或猜測傷害種類。
- 不同技能欄位或投射物分成不同候選。
- 未知候選不被猜測命名。
- 10,000 次傷害佇列壓力與結束事件保留。

## 第一次實機診斷

1. 非戰鬥狀態按 F1，確認不會開啟舊 WPF 設定窗，也不改變游標、鏡頭、人物或攻擊輸入；按 F2 後確認日誌只出現一次歸零事件。
2. 先以坐騎或隊伍帕魯攻擊一般野生帕魯，再換另一隻帕魯攻擊野外 Boss。
3. 如要驗證基地場景，讓至少兩隻基地帕魯參與同一場戰鬥。
4. 從即時儀表與日誌確認每隻帕魯有獨立來源列、各技能傷害正確，目標死亡不會自動歸零。
5. 測試 Alt+Tab、傳送讀取及返回遊戲；HUD 應重新置頂，啟動與自動重啟時不應留下黑色 Windows Terminal。若手動結束外部 HUD PowerShell，約 5–10 秒內應自動重新出現；啟動器故障時最多重試三次後必須停止，不得無限閃現。`skill_dps_hud_overlay.log` 可追查顯示層錯誤。
6. 從 `UE4SS.log` 檢查 `damage-sample` 與 `diagnostic-candidate` 的來源個體、技能候選與傷害。
7. 對持續傷害、多段傷害與無投射物近戰技能各做一次驗證。

離線測試不能證明 Palworld 實際反射結構；尤其基地工作帕魯的訓練家歸屬仍需實機讀回。完成上述讀回前，狀態只能標示為「本機離線驗證」。
